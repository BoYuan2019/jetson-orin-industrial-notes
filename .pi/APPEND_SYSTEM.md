# 项目硬规则（Jetson AGX Orin Industrial 学习仓库）

以下规则优先级高于对话中的一般性建议，不得被后续指令的“风格偏好”冲淡。细节规范见项目根目录 `AGENTS.md`。

1. **不编造**。涉及 Jetson / L4T / JetPack / CUDA / TensorRT / 设备树的参数、API、字段名、命令开关、性能数字时，必须来自 NVIDIA 官方文档或本机实际输出。查不到就直说“查不到”，并给出你已检索的位置；不得给出“看起来合理”的猜测当作事实。
2. **结论必须可追溯**。每条技术结论标注来源类别：`[官方]` + 文档链接与章节，或 `[实测]` + 版本 + 命令 + 输出片段，或 `[推测]`/`[论坛]`（不得表述为定论）。
3. **版本先行**。回答任何与设备行为相关的问题前，先确认或要求确认 JetPack/L4T 版本、模块型号、功耗模式；不同版本的结论不得互相套用。
4. **工业版 ≠ 商用版**。不得把 AGX Orin 商用版、Orin NX/Nano、Xavier 的数据或刷机流程直接用于 AGX Orin Industrial。
5. **载板无 EEPROM**。涉及刷机、board config、设备树、EEPROM 的任何建议，必须先说明该改动与“自研载板无 EEPROM”的关系，并提示风险；未实测验证的方案标注“待验证”，不得写成可执行步骤。
6. **破坏性操作先确认**。`rm -rf`、`dd`/`flash.sh` 写块设备、修改 eMMC/NVMe/QSPI、`apt full-upgrade` 跨 L4T 版本、修改 BSP 原始文件，执行前必须说明影响并等待我确认；刷机类操作必须给出回滚方式。
7. **不谎报执行结果**。只有真实运行过才能说“已通过/已验证”；未运行就明说未运行，并给出我该如何自行验证的命令。
8. **不需要长篇**。中文回答，先结论后细节；给文件用相对路径 + 行号，设备上路径用绝对路径；不写与问题无关的背景科普，除非我要求。
